## Directory Structure

```text
data/
├──processed/                     # Converted/processed .csv for trajectory (optional)
│  ├── sitl/
│  │   ├── train/                 # Training data for model fitting
│  │   ├── valid/                 # Validation data for hyperparameter tuning and model selection
│  │   └── id_test/               # In-distribution (ID) test data for trained model evaluation
│  │       ├── run_XXX_px4.csv    # .csv contatining PX4 trajecectory, features, segmentation results
│  │       ├── run_XXX_ardu.csv   # .csv contatining Ardupilot trajecectory, features, segmentation results
│  │       └── run_XXX_cogni.csv  # (optional) .csv contatining Cognipilot trajecectory, features, segmentation results
│  │ 
│  ├── flight/
│  │   └── ood_test/              # Flight data corresponds to out-of-distribution (OOD) test data, representing sim-to-real gap
│  │       ├── run_XXX_px4.csv    # .csv contatining PX4 trajecectory, features, segmentation results
│  │       ├── run_XXX_ardu.csv   # .csv contatining Ardupilot trajecectory, features, segmentation results
│  │       └── run_XXX_cogni.csv  # (optional) .csv contatining Cognipilot trajecectory, features, segmentation results
│  │ 
│  └── manifest.csv               # manifest data contatining date, run identity, data origin (sitl vs flight), file path (processed file)
│
├── YYYYMMDD_sitl_logs/           # Raw logs generated during SITL execution
│   ├── README.md                 # SITL experiment configuration description
│   └── run_XXX/                  # Each run corresponds to a single simulation instance
│       ├── px4_logs/             # Successful .ulg, process logs, result.json; active runtime state
│       ├── ardu_logs/            # Successful logs/*.BIN, process logs, result.json; active runtime state
│       ├── px4_attempts/         # Only created for unsuccessful PX4 attempts
│       │   └── session_<UTC>_<ID>/
│       │       ├── scenario.yaml
│       │       ├── generated/   # Vehicle/world snapshot, when present
│       │       └── attempt_001/ # Flight/process logs, runtime state, result.json
│       ├── ardu_attempts/        # Same structure for unsuccessful ArduPilot attempts
│       └── cogni_logs/           # (optional) TBD
│
├── YYYYMMDD_flight_logs/         # Processed logs from real flights or external data
│   ├── README.md                 # Flight data description
│   ├── all_runs/                 # Raw, unprocessed, concatenated .csv trajectory data (optional, vision-derived)
│   └── run_XXX/                  # Each run corresponds to a single flight execution
│       ├── px4_logs/             # Raw .csv file (vision-derived), .ulg file (flight record), .mcap file (MoCap) and other metadata
│       ├── ardu_logs/            # Raw .csv file (vision-derived), .BIN file (flight record), .mcap file (MoCap) and other metadata
│       └── cogni_logs/           # Raw .csv file (vision-derived), TBD file (flight record), .mcap file (MoCap) and other metadata
│
└── README.md                     # This README file
```

---

A first-attempt success creates no `px4_attempts/` or `ardu_attempts/` folder.
Failures remain archived even if a later retry succeeds. `result.json` records
attempt number, UTC start/end times, duration, exit code, status, and flight-log
paths. Archives use unique sessions across launcher invocations and survive
`--force`; normal plotting continues to use `px4_logs/` and `ardu_logs/`.

## Dataset Description (Common)
- This repository contains flight data generated from multiple flight stacks:
  - [PX4](https://github.com/PX4/PX4-Autopilot)
  - [ArduPilot](https://github.com/ArduPilot/ardupilot)
  - [Cognipilot](https://github.com/CogniPilot)
- Logs are generated using **Software-In-The-Loop (SITL)** simulation environments.
- The dataset is designed for:
  - Comparative analysis between flight stacks
  - Motion-based firmware identification
  - Machine learning and classification tasks

---

## Data Format
- Raw Logs
  - PX4 SITL(flight) log: .ulg
  - ArduPilot SITL(flight) log: .BIN
  - Cognipilot SITL(flight) log: (TBD)
  - MoCap flight trajectory log: .csv
  - Vision-derived flight trajectory log: .csv

- Processed Logs
  - All: .csv format (standardized for analysis)
  - Typical fields may include:
    - Position (x, y, z)
    - Derived quantities
      - Velocity
      - Acceleration
      - Jerk
      - Heading
      - Yaw rate
      - Curvature

---

## Notes
- Differences between datasets may arise from:
  - Flight control algorithms
  - State estimation (e.g., EKF implementations)
  - Even under similar conditions:
    - Trajectories may vary slightly
    - Timing and control responses may differ

- Detailed experiment configurations are stored separately:
  - `sitl_logs/metadata.yaml`
    Simulation setup (mission, parameters, vehicle models, etc.)
  - `flight_logs/metadata.yaml`
    Experiment setup (if applicable)
